# Full v0.7 synthetic dataset handoff

Member B's synthetic-data milestone turns the retained GMD loops into a drum
library and matching fake beatbox queries. The neural model retrieves matching
library clips; these pairs are not an audio-to-audio generation target.

## Contents

| Split | Source loops | Drum renders | Sloppy queries | AVP participants |
|---|---:|---:|---:|---:|
| Train | 6,904 | 34,520 | 13,808 | 20 |
| Validation | 846 | 4,230 | 1,692 | 3 |
| Test | 893 | 1,786 | 1,786 | 5 |
| Total | 8,643 | 40,536 | 17,286 | 28 |

There are 8,626 distinct source rhythm labels. All retained source loops are
included, including separate performances of the same pattern within one split.
Three clashing training copies were removed by the catalog's most-held-out rule.

Train and validation use Black Pearl, Red Zeppelin, Blonde Bop, Blonde Bop HR,
and DRSKit. Test uses MuldjordKit and Salamander. Gogodze is excluded because
its kit split is unset. E-GMD audio remains on hold; this build uses GMD MIDI.

Each source loop gets one seeded participant from its split and two queries:
Personal and Fixed. Both isolated and improvisation source sounds are eligible.
The saved 20/3/5 participant assignment is unchanged. These are two synthetic
views, not all possible participant/pattern combinations. Full-set clean audio
is not duplicated; clean references remain in the small review checkpoint.

Every render uses the recorded tempo, the spec's 0.25-second lead-in, and a cut
at the end of bar two with a 20 ms fade. Queries apply the approved speed limits
before jitter, then stop each mouth sound at the next actually played sound.
Dropped hits cannot interrupt sounds. Offset, jitter, drops, and white noise
are seeded; tempo drift is off. Labels remain the original source rhythm.
Normalization aims for -20 dBFS RMS with a -1 dBFS peak ceiling, followed by the
ending fade; clips limited by the peak ceiling can have lower RMS.

## Files for C and D

- `manifests/library_manifest.csv`: every drum render and its source, rhythm,
  kit, split, tempo, and audio path.
- `manifests/query_manifest.csv`: every sloppy query, its rhythm, participant,
  mode, split, and realized augmentation settings.
- `manifests/avp_participant_splits.csv`: the fixed participant partition.
- `manifests/dataset_build.json`: counts, source/code fingerprints, seed,
  exact tested C branch revision, check result, and regeneration command.

The source note lists and rhythm grids remain in
`results/gmd_catalog/loops.jsonl`, regenerated by the build command.

The first two manifests keep the columns in `docs/README.md` section 12 and add
provenance columns. `source_clip_id` links each view to the source GMD window.
`midi_path` and `audio_path` are relative to the repository root. Pass that root
as C's `audio_root`. A query can match several kit renders and occasionally
several source performances with the same rhythm. Use the pattern matching
rules rather than assuming one `target_clip_id` per query.

Audio lives under `data/datasets/v07/audio/`, excluded from Git. Pulling code
and CSVs does not download or create audio. Teammates must regenerate it or
receive the dataset directory separately. No audio or model weights should be
added to the commit.

## Regenerate on another machine

Use Python 3.11+ and the project's documented environment. The checked laptop
uses Python 3.13; `requirements-lock.txt` records the dependency versions.
Install SciPy via the lightweight handoff extra; PyTorch is not required for
the loader check.

```bash
python3.13 -m venv .venv
.venv/bin/pip install -e '.[dev,handoff]'
.venv/bin/python -m tools.download_datasets gmd avp
.venv/bin/python -m tools.download_datasets drskit muldjordkit salamander salamander_sfz avl_black_pearl avl_red_zeppelin avl_blonde_bop avl_blonde_bop_hr
git fetch origin c/model-core
.venv/bin/python -m src.build_dataset --seed 0 --publish --model-ref 2730c81101ab276080a60c066a497f7d5c16d629
```

The last line is the seeded build-and-check command. It rebuilds the catalog,
extracts AVP utterances if needed, renders the seven-kit library and both query
modes, checks C's actual loader/features on every audio file, and then copies
the complete manifests into `manifests/`. It exports the required model files
from that exact Git revision temporarily, without merging C's branch into main.
The check tests R1 features, batch construction, positive matches, disjoint
patterns and participants, kit assignment, finite/nonzero audio, and clip framing.
It does not train a model or establish retrieval accuracy.

For a quick all-kit smoke test instead of the full build:

```bash
.venv/bin/python -m src.build_dataset --seed 0 --limit-per-split 2 --out results/full_smoke_local
.venv/bin/python -m tools.check_model_loader --dataset results/full_smoke_local --model-ref 2730c81101ab276080a60c066a497f7d5c16d629
```

A limited build cannot publish production manifests. The existing small v0.7
checkpoint remains available through `python -m src.build_checkpoint --seed 0`.

## Resume, provenance, and listening

Re-running the full command resumes completed files after checking their SHA256
hashes. Missing or damaged outputs regenerate. An interrupted final receipt is
discarded and regenerated. A changed source/spec/code recipe requires a new
`--out` directory and leaves previous audio intact. Reuse seed 0 because another
seed would change the already saved participant partition. Avoid changing source
code during a build. Each kit is rendered separately to bound sampler memory.

Under `data/datasets/v07/`:

- `summary.json` and `build_settings.json` describe the full build.
- `library_receipts.jsonl` records manifest rows and output hashes.
- `query_receipts.jsonl` additionally records every source utterance, clean and
  jittered start, drop decision, realized vocal interval, and choke fade.
- `loader_check.json` records the pinned C revision and per-file feature shapes.
- `SOURCES.md` preserves raw dataset/kit source and license information.
- `preview.html` provides 24 sloppy queries and matching drum targets for a
  listening sample. Open it in a browser after generation.

Every generated query is checked for non-overlapping vocal intervals before
noise is added. White noise can still be audible between vocal hits. The
automated checks establish technical compatibility, not musical realism.
Joshua's final go/no-go listen is required before calling this the musical data
freeze. No automatic commit, push, or message to teammates is performed.

This completes the full synthetic beatbox/library handoff. Real team recordings,
tap-query coverage, enrollment/few-shot experiments, and later musical revisions
remain separate project work in the team plan.
